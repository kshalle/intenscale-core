# perl-perl4 -- the Perl interpreter workload, bare metal

Upstream: `../../interpreter-perl/perl-4.036` (GPL-1+/Artistic).  **Not edited.**

## What this port adds

| File | Why |
|---|---|
| `config.h` + `mkconfig.py` | perl 4's `config.h` is generated by `Configure`, which needs a shell the target does not have.  `mkconfig.py` derives ours from the copy upstream ships (July 1992): it switches off 71 defines and rewrites 5.  Every change is annotated in the generated file, so it can be audited against upstream. |
| `bm_os_stubs.c` | `sys_errlist`/`sys_nerr`, which newlib does not export.  Filled from `strerror()` in a constructor so `$!` still produces real error text -- setting `sys_nerr = 0` would have been less work and would have turned every diagnostic into "Unknown error". |
| `workload/primes.pl`, `workload/anagram.pl` | The workload, written for this suite: prime sieving and factorisation for the numeric and hash paths, anagram grouping for strings, sorting and regex. |
| `workload/mkwords.awk` | Generates the anagram word list.  A real dictionary is someone else's copyrighted content; this emits a deterministic synthetic list from a fixed LCG over an eight-letter pool, which produces genuine anagram classes and doubled letters. |

Everything else it needs -- `fork`, `exec`, `wait`, `pipe`, `getuid`, `chdir`,
`umask`, `utime`, `alarm`, `sleep`, `ioctl`, `sigaction`, `select`, `sysconf`
-- comes from the harness (`../common/bm_posix_stubs.c`), which the XLISP
port established.  perl reaches for all of them at startup or on paths it never
takes with these scripts.

## Running

    make run-spike SIZE=tiny
    ../scripts/run-verilator.sh perl-perl4.riscv workload/primes.pl 400 100

Sizes are workload arguments, not compile-time constants, so switching size
needs no rebuild.  Measured on spike (instructions):

| | primes | anagram |
|---|---|---|
| tiny | 22 M | 11 M |
| small | 89 M | 76 M |
| ref | 709 M | ~300 M |

## Verification

Both scripts are written in the Perl 4 subset, so they also run on a modern
host perl, and the output diffs clean:

    diff <(perl workload/primes.pl 400 100) \
         <(spike --isa=rv64imafdc perl-perl4.riscv workload/primes.pl 400 100 | grep -v '^\[bm\]')

Byte-identical against host perl 5.40.1 for both workloads.  (The anagram
script breaks ties on the class key rather than on hash iteration order
specifically so this comparison is meaningful -- perl 4 and perl 5 walk a hash
in different orders.)

## The one that cost real time: which perly.h wins

perl 4 generates its parser at build time and *expects the regenerated
`perly.h` to replace the copy in the source directory*.  Two things then
collide:

1. The shipped `perly.h` numbers its first token 257 (AT&T yacc).  bison
   reserves 257 for its own `YYUNDEF` and starts at 258.
2. A quoted `#include "perly.h"` searches the including file's own directory
   first -- so `toke.c`, which lives upstream, always found the stale shipped
   header no matter what `-I` said.

The lexer therefore returned token codes one lower than the parser expected,
and *every* statement was a syntax error -- including `print "hello\n";` --
while the build itself looked perfectly healthy.  The fix is `-I-` in
`BM_CFLAGS`: it removes the includer's-directory rule, so the explicit `-I`
order decides and our generated header wins.  `-I-` is deprecated in favour
of `-iquote`, but `-iquote` does not turn that rule off, which is the whole
point here.

Two consequences of getting our header in front of upstream's:

- bison's header defines `YYDEBUG` (as 0), and `toke.c` tests it with
  `#ifdef`, not `#if`, then uses perl's `debug` global, which only exists in a
  `-DDEBUGGING` build.  The Makefile appends `#undef YYDEBUG` to the generated
  header; the parser's own `#if YYDEBUG` blocks still evaluate false.
- `perly.fixer` is not used.  It patches AT&T/BSD yacc output from 1991 for
  parser-stack growth bugs that bison does not have.

## Perl 4, not Perl 5

Worth knowing when writing workloads: no `scalar(@array)` (use `$#a+1`), user
subs are called as `&f(...)`, and `reverse` of a string needs an explicit
scalar context.  `sort { ... }` blocks, C-style `for`, hashes, `s///g`,
`split //`, `printf` and file I/O through `open` all work.

## The Linux build

`make BM_ENV=linux` compiles the same sources against glibc, with the same
`config.h` -- deliberately, so the interpreter has the same features
configured in both environments and the workloads exercise the same code.  It
needs one flag: `-DI_TIME`.

perl 4's `config.h` leaves `I_TIME` off and `I_SYS_TIME` on, which was right
for the systems it was configured against, where `<sys/time.h>` declared
`struct tm` as well as `struct timeval`; it is right for newlib too.  glibc
separates them, so without `-DI_TIME` `dolist.c` gets `struct tm` from
nowhere and the `localtime`/`gmtime` builtins fail to compile -- about forty
errors, all of them "invalid use of undefined type".

The two builds' workload output is **byte-identical**, which for an
interpreter across two libcs and two compiler generations is the strongest
check this port has.  It is byte-identical across two *Linux hosts* as well
(glibc 2.41 and 2.35), for both workloads.

### Two linker warnings, both expected

    ld: eval.c: warning: Using 'setpwent' in statically linked applications
        requires at runtime the shared libraries from the glibc version used
        for linking

`setpwent`, `endpwent`, `setgrent` and `endgrent` -- glibc loads its
name-service backends with `dlopen`, so a static binary containing them is
not self-contained *along those paths*.  perl 4 links them because `eval.c`
implements `getpwent`/`getgrent` for scripts that want them.  No workload
here does a user or group lookup, so the paths are never entered; if a script
did call them on a host without matching `libnss_*` modules, the lookup would
fail rather than crash.  This is the only port in the suite that links any
such function.

    ld: perl.c: warning: the use of `mktemp' is dangerous, better use
        `mkstemp' or `mkdtemp'

perl 4's own code in `main`, from 1991, unreached by these workloads.  The
vendored tree is not edited, so the warning stays.
